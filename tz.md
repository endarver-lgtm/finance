## 2. Этап A. Данные

### A1. Курс на момент операции

**Проблема.** Все пересчёты идут по текущему `usd_rate`/`eur_rate`. История «плывёт» при каждом обновлении курса, баланс копилки в USD меняется без операций.

**Сделать.**

- Добавить в `budget_entries`, `income_entries`, `savings_entries`, `debts` колонки: `rate_usd REAL`, `rate_eur REAL`, `amount_byn REAL`, `fx_source TEXT` (`entry` | `backfill`).
- При создании записи сохранять текущие курсы и считать `amount_byn = amount × курс валюты записи` (для BYN курс 1).
- Бэкфилл старых строк: текущими курсами, `fx_source='backfill'`.
- В формы расхода и дохода в валюте добавить необязательное поле «Списано банком, BYN». Если заполнено, `amount_byn` берётся из него (банк берёт свой курс, а не курс НБРБ).
- Все агрегаты за период (Inc, Exp, Dep и т. д.) суммируют `amount_byn`, а не пересчитывают по текущему курсу.
- Баланс копилки считать в валюте цели: каждая запись переводится из валюты записи в валюту цели **по курсам этой записи** (хелпер `convert_at_entry(entry, target_ccy)`). Для показа в BYN допустима переоценка остатка по текущему курсу (это остаток, а не поток).

**Готово, когда:** изменение `usd_rate` в настройках не меняет ни одну сумму за прошлые периоды и баланс копилки в её валюте (тест H-9).

### A2. Сверка: курсовая разница

**Проблема.** 100 USD вчера и сегодня стоят по-разному. Эта разница попадает в «Неучтёнку» как фиктивная недостача или излишек.

**Сделать.**

- В `balance_checks` добавить `rate_usd`, `rate_eur` (курсы на момент сверки) и `fx_effect_byn REAL`.
- Для регулярной сверки: `fx_effect = Σ по валютам (остаток_валюты_прошлой_сверки × (курс_сейчас − курс_прошлой_сверки))`, остатки берутся из `real_breakdown` прошлой сверки.
- `diff_clean = diff − fx_effect`. Корректировка в «Неучтёнку» создаётся только на `diff_clean`. `fx_effect` сохраняется и показывается в истории сверок отдельной колонкой «Курсовая разница».
- Допуск `|diff_clean| ≤ 0.005` считается «Сошлось».

### A3. Флаг фиксированных конвертов

- В `budget_categories` добавить `is_fixed INTEGER NOT NULL DEFAULT 0`.
- Бэкфилл: `period='month'` → 1, `period='week'` → 0, `track_only=1` → 0. Дать переключатель в форме редактирования конверта («Фиксированный платёж: аренда, связь, подписки»).

## 3. Этап B. Единые определения (`services/metrics_core.py`)

Все суммы в BYN по `amount_byn`, за период `[from, to]`. Корректировки сверки определяются по `balance_checks.adjust_income_id` и `adjust_expense_id`.

| Символ | Определение |
| --- | --- |
| `Adj_inc` | доходы, на которые ссылается `adjust_income_id` |
| `Adj_exp` | расходы, на которые ссылается `adjust_expense_id` |
| `Inc` | все доходы минус `Adj_inc` |
| `Exp_own` | расходы с `from_goal_id IS NULL` минус `Adj_exp` |
| `Exp_goal` | расходы с `from_goal_id IS NOT NULL` (равны сумме `withdraw_spent`; проверять в тесте) |
| `Exp_all` | `Exp_own + Exp_goal`: «потреблено», база для аналитики расходов |
| `Dep`, `W_free`, `W_spent` | взносы; возврат в свободные; снятия на покупку |
| `NetSave` | `Dep − W_free − W_spent`: чистое пополнение накоплений |
| `ΔB` | как сейчас (долги) |
| `Adj_net` | `Adj_inc − Adj_exp` |
| `CashFlow` | `Inc − Exp_own − Dep + W_free − ΔB + Adj_net` |

**Регресс:** `CashFlow` для любого периода равен прежнему `Free` (корректировки просто вынесены из строк дохода и расхода в отдельную). Этот тест обязателен.

**Правила для всех функций:**

- «Неучтёнка» и корректировки исключены из `Inc` и `Exp_*` везде, где считается аналитика (сбережения, подушка, дневной расход, Парето, сдвиги, дисциплина).
- Хелпер `history_months(today, window_days=90)`: возвращает `min(window_days, дней с первой записи пользователя) / 30.4375`. Если дней меньше 14, возвращает `None` («мало данных»).
- Все деления на `Inc` и расходы: если знаменатель ≤ 0, возвращать `None`, а не подставлять `0.01`.

## 4. Этап C. Показатели

### C1. Норма сбережений

**Было:** `max(0, Dep − W_free) / max(0.01, Inc)`. Трата из копилки не вычитается, в доход попадает «Неучтённый приход». **Стало:**

- Основной: `SR = max(0, NetSave) / Inc × 100%` (`None`, если `Inc ≤ 0`).
- Дополнительный (подпись «Профицит»): `Surplus = (Inc − Exp_all) / Inc × 100%`. Показывается мелко под основным числом.
- Пороги прежние: ≥20% ok, 10–20% warning, <10% danger. **Пример-тест:** доход 1000, взносы 300, покупка из копилки 200 → `SR = 10%`, а не 30%.

### C2. Подушка безопасности

**Было:** все копилки (включая `want`, `big`) делятся на `AvgExp90 = Σ/3.0`. **Стало:**

- `Reserve = Σ по целям type='reserve'` (остаток в BYN по текущему курсу).
- `AvgExp = Exp_all за окно / history_months()` (окно 90 дней, `None`, если истории < 14 дней).
- `R = Reserve / max(AvgExp, 1.0)`.
- Нет целей `reserve` → статус «Нет резерва» с ссылкой «Создать резерв», числа не показывать.
- Вторая строка мелко: «со всеми копилками: X мес».
- Пороги прежние (≥6 / 3–6 / 1–3 / <1). **Пример-тест:** reserve 1000, big 3000, расход 800/мес → `R = 1.25`, статус «Минимум».

### C3. Дисциплина бюджета

**Было:** доля конвертов в лимите в текущем (неполном) месяце, бинарно. **Стало:**

- Окна: недельные конверты — последние 8 **закрытых** недель (ISO), месячные — последние 3 **закрытых** месяца. Учитывать только периоды после `created_at` конверта.
- Единица учёта: пара (конверт, период). `Adh = доля пар, где Spent_own ≤ лимит периода`. Лимит и траты считать по `Exp_own` конверта.
- Исключить `track_only` и конверты с лимитом 0.
- Второй показатель: «средний перерасход» = среднее `max(0, Spent/лимит − 1)` по пересекшим лимит парам.
- Закрытых периодов нет → `None` («мало данных»). Текущий период показывать отдельной строкой «сейчас: X из Y конвертов в темпе» (см. E2).
- Пороги: ≥80% ok, иначе warning.

### C4. Дневной расход, «можно тратить в день»

**Было:** весь `Exp_own` месяца / прошедшие дни. **Стало:** два показателя в одной карточке.

- `BurnVar = Exp_all по конвертам с is_fixed=0 за месяц / прошедшие дни` (минимум 1 день).
- `SafePerDay = Σ по переменным конвертам [лимит_периода − Spent_own] / дни до конца периода конверта` (для недельных конвертов конец недели, для месячных конец месяца). **Минус не обнулять:** при перерасходе показывать отрицательное число красным.
- Прогноз месяца: `Forecast = Exp_all_месяца_на_сегодня + BurnVar × оставшиеся_дни + невыплаченные_фиксированные` (фиксированный конверт без трат в этом месяце: плановый лимит).
- Подпись под числом: «Темп: X BYN/день, прогноз месяца: Y».

### C5. Структура трат (Парето)

**Стало:**

- База: `Exp_all` месяца, без корректировок, по умолчанию **без** `is_fixed=1` (переключатель «Показать фиксированные»).
- Сортировка по убыванию, накопленная доля. «Ядро» = минимальный набор категорий, накопленная доля которого ≥ 80% (включая пересёкшую порог).
- Категорий < 5 → вместо диаграммы строка «Мало категорий для анализа».
- Визуализация: горизонтальные столбцы по убыванию + линия накопленной доли (вместо кольцевой диаграммы). 12-цветную палитру оставить для столбцов, ядро отметить подписью «Ядро».
- Траты из копилок включены и помечены значком.

### C6. Сдвиги к прошлому месяцу

**Риск:** сравнение неполного текущего месяца с полным прошлым (15-го числа всё «сэкономлено на 50%»). Проверить в коде. **Стало:**

- Сравнивать период «с 1-го по d-е число» текущего месяца с «1-е по min(d, дней в прошлом месяце)-е» прошлого. Подпись: «к тому же дню прошлого месяца».
- База: `Exp_all` без корректировок. Показывать топ-3 роста и топ-3 экономии.
- Не показывать категории, где обе суммы < 20 BYN или изменение < 10%.
- 1-го числа (d=1) без данных: «мало данных». **Пример-тест:** 15-е число, траты 400, в прошлом месяце к 15-му 420 → −4,8%, а не −50%.

### C7. Прогноз целей (ETA)

**Было:** `Pace = (Σ deposit − Σ withdraw за 90 дней) / 3.0`. Цель создана недавно → темп искажён. Нет самого полезного числа: сколько нужно откладывать. **Стало** (по каждой цели, в валюте цели, по курсам записей из A1):

- `окно = min(90 дней, дней с первой записи цели)`. Окно < 14 дней → «Мало данных».
- `Pace = (deposit − withdraw_free − withdraw_spent за окно) / (окно / 30.4375)`.
- Если дедлайн в будущем: `Required = (Target − Current) / ((Deadline − Today) / 30.4375)`. Дедлайн в прошлом и цель не достигнута → статус «Просрочено».
- Если `Pace > 0`: `ETA = Today + (Target − Current) / Pace × 30.4375` дней.
- Карточка: «Нужно X/мес · сейчас Y/мес · ETA дата». «В графике» при `Pace ≥ Required`, иначе «Отстаёт». Цель без дедлайна: только Pace и ETA. Цель достигнута: «Готово». **Пример-тест:** цель 1200, баланс 300, окно ровно 2 месяца (60,875 дня), взносы 300 → `Pace = 150`, осталось 6 мес. Дедлайн через 4 мес → `Required = 225`, статус «Отстаёт».

### C8. Водопад Cash Flow

**Стало** (цепочка должна сходиться с итогом): Приходы (`Inc`) → −Конверты (`Exp_own`) → −Взносы (`Dep`) → +Возвраты из копилок (`W_free`) → −Долги (`ΔB`, строка только если ≠ 0) → ±Корректировки сверки (`Adj_net`, только если ≠ 0) → **= CashFlow**.

- Траты из копилок (`Exp_goal`) вне цепочки: подпись под водопадом «Из копилок потрачено: X (на поток не влияет)».
- Чип в шапке «Остаток» переименовать в «Чистый поток». **Инвариант:** сумма столбцов равна `CashFlow` (допуск 0.005) для любого периода.

### C9. Тренды за 6 месяцев

- Серии: `Inc`, `Exp_all`, `NetSave` по месяцам (`amount_byn`).
- Текущий неполный месяц рисовать пунктиром, подпись «в процессе», **в средние не включать**.
- Средние считать по закрытым месяцам, где есть данные (месяцы до первой записи исключить).
- «Итоговый свободный остаток за полгода» → «Чистый поток за 6 мес» (сумма `CashFlow` по закрытым месяцам).

### C10. Точность учёта (новая карточка)

- `Unexplained = Adj_inc + Adj_exp` за 30 дней (оба значения по модулю).
- `Точность = 100% − Unexplained / (Exp_all + Adj_exp)`; знаменатель ≤ 0 → `None`.
- Пороги: «Неучтённого» ≤ 2% ok, 2–5% warning, > 5% danger. Показывается в блоке сверки на дашборде и в аналитике.

## 5. Этап D. `planning.py`

### D1. Масштабирование по дням

**Убрать** таблицу множителей ×4, ×52, ÷30, ÷4 (недели и месяцы не делятся на целое). **Правила:**

- Если единица плана совпадает с единицей просмотра (месячный конверт в месячном виде, недельный в недельном), значение равно лимиту без пересчёта.
- Иначе через ставку в день: недельный → `amount / 7`; месячный → `amount × 12 / 365`. Значение за диапазон = ставка × число дней диапазона (для календарного месяца точное число его дней).
- Год: недельный × `365 / 7` (≈ 52,14), месячный × 12.
- Одна функция `scale_plan(amount, plan_period, range_from, range_to)` на весь проект; везде заменить старые вызовы. **Проверка:** недельный 100 в 30-дневном месяце = 428,57; месячный 400 в неделе = 92,05; недельный 100 за год = 5214,29; месячный 400 за год = 4800; месячный 400 в месяце = 400.

### D2. Разовые доходы

- `income_sources.expected_date TEXT NULL` (поле «Ожидаемая дата» в форме). Бэкфилл: дата `created_at`.
- План разового дохода учитывается в периоде, содержащем `expected_date`, **и не обнуляется после получения** (старое правило «факт ≥ плана → план 0» удалить).
- Статусы: `received` (факт ≥ план), `partial`, `pending`, плюс `overdue` («Просрочено»: `expected_date < today` и не получен).

### D3. Регулярные доходы с датами

- `income_sources.pay_days TEXT NULL` — JSON-список чисел месяца, например `[5, 20]` (аванс и зарплата). `planned_amount` в этом случае — сумма одной выплаты.
- Календарь ожидаемых поступлений строится по `pay_days`; если даты не заданы, источник показывается без даты и подписью «дата не указана».

## 6. Этап E. Полоски лимитов и темп

### E1. Честная полоска

- Убрать `min(100, …)`: `pct = Spent_own / limit × 100` без верхней границы.
- Полоска визуально заполнена до 100%, при превышении красная с подписью «+X BYN сверх лимита». «Осталось» может быть отрицательным (красным).
- Пороги в `constants.py`: `< 80` ok, `80…<100` warning, `≥ 100` danger. README и SPECIFICATION берут те же значения (сейчас там 75/99 и 80/100).

### E2. Темп по конверту

- Для конвертов с лимитом > 0 и не `track_only`: `elapsed = прошло дней / дней в периоде`; со 2-го дня периода (в 1-й день темп не показывать).
- `ratio = (pct / 100) / elapsed`. `≤ 1.0` ok, `1.0…1.25` warning «опережаете график», `> 1.25` danger.
- На карточке: «Темп: на X% выше/ниже графика» и «можно ещё Y BYN в день». Статус карточки — худший из статуса по `pct` и статуса по темпу.

## 7. Этап F. Интерфейс

- «Свободный остаток» переименовать в «Чистый поток» (дашборд, аналитика, README, SPECIFICATION). Подсказка (i): «Приход минус расходы, взносы и долги за период. Это не сумма на руках».

- Новая карточка «Можно тратить в день» = `SafePerDay` (C4), красная при значении < 0.
- Любой показатель с `None` показывать как «—» с причиной в подсказке.

- Под отчётом подпись: «Расчёты — приложение, текст — ИИ».

## 9. Этап H. Тесты

Новый файл `scripts/test_analytics.py`, запускается из `verify_db.py`. База сидируется записями, вызывается `metrics_core`, допуск 0.005.

| № | Проверка |
